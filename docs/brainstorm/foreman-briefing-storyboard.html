IP Corporation Workbench · Design Storyboard

The Foreman Briefing

Six chapters replace the Today dashboard as the landing experience. Chapter transitions are cinematic; controls inside a chapter are fast and plain. A recurring blueprint structure assembles as the briefing proceeds: fragmented at arrival, ordered by the end, which is the product's actual job made visible. Quick Brief and Current State stay one keystroke away at every moment. Two journeys share this grammar: the morning briefing, and a per-meeting countdown that begins from a toast thirty minutes before each meeting and ends with the desk physically set.

Journey Two · Per Meeting

The Meeting Countdown

Thirty minutes before each real meeting, a toast offers the countdown. Clicking it opens a short guided prep for that specific meeting: the room, last time, open threads, today's goal, materials. The final chapter hands the desk to the automation lane: Cluely set to IP Corp meeting mode with the prep file uploaded and told to use it, a new session started, everything else minimized, prep documents open in the background, every step receipted.

Laws of the experience

  1. Scroll, wheel, arrows, and gestures navigate. They never approve, dismiss, snooze, or execute. Actions require explicit controls and save receipts.
  2. Every count and claim comes from the live snapshot, fail-closed. A failed source renders as the amber disclosure line, never an invented number.
  3. Guided plays on the first visit of the day and resumes where you stopped. Quick Brief and Current State stay visible always; Esc skips any transition.
  4. Cinematic between chapters, 300 to 600ms inside them. A three-item briefing costs 2 to 4 minutes and is fully keyboard-completable.
  5. Item cap of 3 to 5 with the remainder visibly parked; snoozes return on a date or new activity, whichever comes first.
  6. v1 is layered CSS, SVG, and canvas with compositor-only animation. No WebGL requirement; prefers-reduced-motion collapses transitions to fades.
  7. Replies route into Jira and email as drafts and comments, never sends.

Laws of the countdown

  1. Countdown timers come from calendar data a human visit already warmed. Background jobs never start a Microsoft read; a meeting added after the last visit rings only after the next visit refreshes the cache, and the limit is stated, not hidden.
  2. Desktop choreography runs only from an explicit click, never from the toast alone, and refuses to run while a screen share is active.
  3. Every automation step verifies the window and control it is about to touch (restored, correct title, expected element) before acting, and writes a receipt. An unverifiable step stops the run and is reported unverified, not retried blind.
  4. Set the Room is offered only when the per-meeting prep file exists. A missing file is said out loud and generated first; never an empty upload.

State machines

briefing:  arrival → orientation → changes → item-1 → item-2 → item-3 → day-plan → clear   (any state → quick-brief | current-state; every transition skippable)
countdown: toast → room → last-time → open-threads → goal → materials → set-room → set   (any state → full-packet | skip; the set-room run starts only from an explicit click)
