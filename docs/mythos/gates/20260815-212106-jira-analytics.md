# Jira analytics acceptance checks

- Created: 2026-08-15 21:21 ET
- Status: frozen before implementation

## Task summary

Add a read-only Jira analytics mode to the existing Work screen. It should turn real MT issue,
worklog, estimate, resolution, and status-history data into useful team flow measures on both
desktop and iPhone.

## User-visible outcome

People can open Analytics beside the existing Jira layouts and quickly understand total time
logged, total time estimated, estimate usage, average time to resolution, average backlog wait,
average time by Jira status, current work by status, and recent completion pace.

Every average states how many issues or visits it represents. Missing history stays visible as a
coverage note instead of being guessed.

## Not included

- No Jira changes, worklogs, comments, transitions, issue creation, or Microsoft 365 calls.
- No invented targets, team comparisons, or synthetic health score.
- No new chart dependency.
- No redesign of the other Jira layouts.

## Acceptance criteria

1. Analytics is a discoverable layout inside Live Jira issues and loads its extra history only
   after the person opens it.
2. The server reads MT issues and status changes, uses limited concurrency, caches the result for
   a short period, and exposes no write path.
3. Headline measures include total logged, total estimated, estimate usage, average resolution
   time, and average backlog wait.
4. Flow detail includes average time per named status, current issue count by status, and recent
   completed-issue pace.
5. Resolution and backlog averages exclude records that lack enough evidence and show exact
   sample sizes and coverage notes.
6. Loading, unavailable, partial-history, and empty states are truthful and usable.
7. Desktop uses the available width without becoming dense. iPhone uses one-column cards,
   readable charts, 44px controls, and no page-level horizontal overflow.
8. Reduced motion and keyboard focus remain supported.
9. Metric calculations have focused tests, including repeated status visits, unresolved work,
   missing dates, and partial changelog failures.
10. TypeScript, focused Biome checks, production build, focused tests, and desktop plus iPhone
    browser checks pass, or any unrelated existing failure is reported exactly.

## Risks

- Fetching one changelog per issue can be slow or hit Jira request limits. Limit concurrency,
  cache successful reads, expose progress, and keep partial results useful.
- Historical Jira status names may not match the current status list. Preserve their readable
  names and classify unknown history honestly.
- The checkout is shared and already has unrelated edits. Use isolated new files plus very narrow
  edits to existing files, then inspect the final diff.

## Rollback

Remove the Analytics mode, client method, server route, and isolated analytics files. The existing
Jira layouts and initiative route continue unchanged.
